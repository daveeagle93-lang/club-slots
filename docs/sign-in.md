# Sign-in options

There are two ways for organisers to sign in to the admin pages. How to use the sign-in screens is in [Signing in](admin-guide.md#1-signing-in) in the admin guide.

- **Admin secret (the default).** One shared admin secret, made once on your new site's first-run page, with a recovery code that makes a new secret if you lose this one. There is no code to choose beforehand. Nothing to configure: with `ADMIN_AUTH` unset the site uses the password. Everyone who administers the club uses the same secret, there is no second factor and no per-person identity.
- **Cloudflare Access (the upgrade for a custom domain).** One-time-PIN emails and a named identity per admin. It needs a domain whose nameservers are managed by Cloudflare ([Cloudflare's migration notes](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/) say custom domains require this). In your own copy's `wrangler.jsonc`, add `vars` (the template has none) with `ADMIN_AUTH` set to `access`, plus `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD`, commit and push so the Worker redeploys, and create the Access application for your custom domain's hostname. Config `vars` overwrite values set in the dashboard on every deploy unless `keep_vars` is set ([Wrangler docs](https://developers.cloudflare.com/workers/wrangler/commands/workers/)); secrets are never deleted by a deploy.
  **Unverified:** whether the `Cf-Access-Jwt-Assertion` header reaches a Worker that serves static assets. Cloudflare's docs say `ctx.access` is not available for such Workers ([Cloudflare Access for Workers](https://developers.cloudflare.com/workers/configuration/cloudflare-access/)) and say nothing about the header; the app checks the header itself. Test the sign-in after you turn Access on. Access can also protect `workers.dev` addresses ([workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)), but the recommendation stays a custom domain.

Details, settings and limits: [admin-auth.md](admin-auth.md). The step-by-step for switching to Access: [Custom domain and Cloudflare Access](deploying.md#custom-domain-and-cloudflare-access) and [handover.md](handover.md#switching-to-cloudflare-access-on-a-custom-domain).
